# Coaching Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. The owner prefers inline execution, committing and pushing after every task.

**Goal:** Players coach their AI in the Playground (thumbs up a good reply, or write the answer they wished for), and the next training run can learn from those lessons.

**Architecture:** Lessons live on the server (R2) like the notebook and loved replies; the world counts them; a plan switch adds them to the run's coaching pairs at 5% of the reading, the trainer's existing `coaching` dataset.

**Tech Stack:** As Stage 2.

**Spec:** `docs/superpowers/specs/2026-11-04-remaining-features-design.md` §3 (decision C45). Builds on Stage 2 (`2026-11-04-stage2-friends.md`): its `textProblem` filter and job owners.

## Global Constraints

- **Sim version:** the next free version when this starts (sim-8 if Stage 2 ended at sim-7). `upgradeState` gives every company `lessons: 0` and every stored plan `coaching: false`.
- **Lessons:** at most 200 per company (the newest replace the oldest); a written answer is 1–500 characters and passes `textProblem`.
- **Plan switch:** enabled from **5 lessons**. Refusal copy: "Your AI needs at least 5 lessons first. You have {n}."
- **Share:** lessons add **5%** of the reading; Learn from customers keeps its own 5%; the shares add up when both are on.
- **R1:** a written answer is never shown as the AI's words; screens label it "Your answer".
- **Button copy:** "👍 Good answer", "✏️ Write a better answer", "Saved as a lesson."

## Review Focus

1. **A reply that is still streaming** (or failed) can't be coached. Owner: Task 2, test "coaching a reply that isn't stored is refused".
2. **A rival's or a friend's AI in the Playground** can't be coached (lessons are for your own AIs). Owner: Task 2.
3. **The same reply liked twice** makes one lesson. Owner: Task 2.
4. **The 201st lesson** drops the oldest, and the count stays 200. Owner: Task 2.
5. **A plan with coaching on whose lessons were deleted below 5** before the run starts is refused at start, not silently trained without them. Owner: Task 1.

### Task 2: The lesson service and the training config

**Files:**
- Create: `apps/server/src/coaching/service.ts`, a migration (`lessons (id serial, world_id uuid, company_id text, question text, answer text, kind text, source_thread uuid, source_idx int, at bigint)`, unique on `(source_thread, source_idx, kind)`)
- Modify: `packages/protocol/src/wire.ts` (client message `lesson {cid, worldId, threadId, idx, kind: "liked" | "written", text?}`; `lessonDelete {cid, worldId, lessonId}`; Query `lessons {worldId}`), `apps/server/src/training/config.ts` and `service.ts` (`lessons` pairs)
- Test: `apps/server/test/coaching.test.ts`

**Interfaces:**
- Consumes: Stage 2's `textProblem(text)`.
- Produces:
  - `lesson` checks:
    - your own chat thread with **your own** AI
    - `idx` is a stored AI message right after a user message
    - `written` needs `text`
  - It stores `{question: that user message, answer: the AI's reply (liked) or the text (written)}`, keeps the newest 200, and submits `lessonsCounted`.
  - Refusals:
    - "Coach your own AI's replies."
    - "Pick a reply from this conversation."
    - the filter's copy
  - `toTrainRunConfig(..., {lessons})`: when `plan.coaching`, the pairs join `coaching` and `mixture.coaching` grows by 0.05, other shares scaled to make room (as Learn from customers does).
