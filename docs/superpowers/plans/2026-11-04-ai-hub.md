# AI Hub and Leaderboards Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. The owner prefers inline execution, committing and pushing after every task.

**Goal:** Players publish AIs to a Hub where anyone on the host's server can try them, and leaderboards rank AIs from every world on the same tests.

**Architecture:**
- The Hub is server-wide (outside any world): a hub entry is a snapshot of an AI's public facts, and a world-best table is updated at each eval.
- Try-it chats with a hub AI are private threads answered by the maker's card (Stage 2 owners).
- Home gains the AI Hub and Leaderboards screens.

**Tech Stack:** As Stage 2.

**Spec:** `docs/superpowers/specs/2026-11-04-remaining-features-design.md` §6 (decisions C41, C42).

## Global Constraints

- **A hub entry** snapshots, at publish time:
  - `{entryId, versionId, worldId, worldName, companyName, aiName}` (the product name if on sale, else "{Company} {label}")
  - `{scores, overall, personalityWords, brain, publishedAt}`
  - plus the maker's display name
  - It never holds plans, cash, notebook or blob keys.
- **Publishing:** the owner only; the version must be scored. "Publish to the Hub" / "Remove from the Hub". Refusal: "Your AI needs its scores first."
- **Leaderboards:**
  - Rank by `overall` and by each of the eight skills: every hub entry, plus each world's best AI (its highest overall so far).
  - A world-best row shows the world name and company name, without Try-it unless it is also published.
  - The rival pack's AIs appear once each, marked "Rival".
- **Names:** guest names and company names only (C41).
- **Try-it:** 10 messages per 10 minutes per asker per AI. Offline copy: "Its maker's computer is offline, so it can't answer right now."

## Review Focus

1. **A published AI whose world was deleted** or whose version was pruned: the entry stays listed, with Try-it disabled ("This AI isn't available to try any more."). Owner: Task 2.
2. **The same version published twice** keeps one entry. Owner: Task 1.
3. **A world-best row** updates when a better AI is scored, and never drops to a worse one. Owner: Task 1.
4. **Hub Try-it from someone who isn't in that world:** allowed, private, and never a member of that world. Owner: Task 2.
5. **Opacity:** no hub response carries any private field (property test). Owner: Task 1.

**Interfaces:**
- Produces:
  - `POST /api/hub {worldId, versionId}` (owner, scored) → `{entryId}`, idempotent per version.
  - `DELETE /api/hub/:entryId` (owner).
  - `GET /api/hub?skill=<category|overall>` → entries, best first.
  - `GET /api/leaderboards?skill=` → `{rows: [{kind: "hub" | "worldBest" | "rival", name, company, world, score, entryId | null}]}`.
